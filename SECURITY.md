# Security Policy

## Project

civwatch-v3: HTML dashboard for unified RF observability (cellular, Wi-Fi, D2D, transport) with an evidence chain, part of the CIVWATCH ecosystem. Defensive monitoring only.

## Supported Versions

No tagged, maintained release lines. Only the latest commit on the default branch (`main`) is supported. This repository is superseded in active development by other CIVWATCH repositories and receives security fixes only.

| Version | Supported |
| --- | --- |
| `main` (latest commit) | Security fixes only |
| Anything else | No |

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub private vulnerability reporting: repository **Security** tab, then **Report a vulnerability**. If that is unavailable, open a public issue titled "Security contact request" with no vulnerability details, and the maintainer will arrange a private channel.

Include: affected file or component and commit, reproduction steps, impact assessment, and any proof-of-concept. Do not include real personal data.

## Expected Response Times

Single-maintainer project. Targets, not guarantees:

| Stage | Target |
| --- | --- |
| Acknowledgement | 5 business days |
| Initial triage and severity assessment | 10 business days |
| Status updates while open | Every 14 days |
| Fix or mitigation for confirmed issues | Severity-dependent; critical prioritized first |

Default coordinated disclosure window: 90 days from acknowledgement, extendable by agreement.

## Scope Notes

- No bug bounty is offered.
- Non-security bugs: use public issues.
